# 参与开发

欢迎提 issue 和 PR。

## 提 issue

说清楚三件事：

1. **你做了什么** —— 命令、配置、点了哪个按钮
2. **你期望什么** —— 正常应该发生什么
3. **实际发生了什么** —— 报错原文、日志片段、截图

报错信息请贴**原文**，不要转述。`TypeError: 'NoneType' object is not subscriptable` 和「说有个空值错误」是两回事。

涉及配置的，把 `config.json` 里**敏感部分去掉**再贴（token、内网地址、真实会话 ID）。

## 提 PR

### 开始之前

改动大的（新增接入方式、改协议、换存储）先开个 issue 聊聊。省得写完发现方向不对。

改错别字、补文档、修明显的 bug，直接提。

### 代码风格

**后端（Python）**

- 只用标准库。这个项目的卖点之一是零依赖，加 pip 包要有充分理由
- 单文件 `server.py`，别拆成一堆模块
- 错误信息写给用户看，不是写给编译器看。`agent id 不合法（字母开头，只含字母数字下划线，最长32）` 比 `invalid id` 有用
- 配置错误一律启动时退出，不要带着坏配置跑起来

**前端（Flutter）**

- 跟现有目录结构走：`models/` `screens/` `services/` `widgets/` `theme/`
- 网络请求都走 `services/api.dart`，别在界面里直接 `http.get`
- 中文字符串直接写，不搞 i18n 文件（这个项目只有中文）

### 提交前自检

```bash
# 后端能不能起来
cd server && python3 server.py

# 配置校验过不过
python3 -c "import json; json.load(open('config.json'))"

# 前端静态检查
cd app && flutter analyze
```

### 提交信息

一行说清改了什么。中文英文都行。

```
修：@ 匹配在名字含空格时截断
加：dsh_http 类型的自动 cookie 续期
改：messages.json 写入改成原子替换
```

### 文档

改了行为就同步改文档：

- 配置字段变了 → `CONFIG.md`
- 协议字段变了 → `protocol.md`
- 用法变了 → `README.md`

文档和代码不同步的 PR 会被要求补。

## 文档写作约定

这个项目的文档只写中文。

几条硬规矩：

- **不出现真实的人名、主机名、路径**。一律用「用户」「agent1」「`/path/to/config.json`」这样的占位
- **不写营销话术**。「业界领先」「革命性」这类词一个都不要
- **数字要有出处**。写「上限 5000 字符」，就去代码里确认是 5000，别估
- **坑要写清怎么发现的**。只写「注意 X」没用，要写「按 Y 写会得到 Z 错误」

## 不接受的改动

- 引入第三方依赖来实现标准库能做的事
- 把单文件后端拆成多模块
- 加遥测、埋点、外部上报
- 把 `config.json` 换成需要联网拉取的配置中心

## 许可

提交的代码按 MIT 许可发布。
